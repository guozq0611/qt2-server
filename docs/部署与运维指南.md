# qt2-server 部署与运维指南

> **适用对象**：新环境部署 / 日常开发 / 运维管理
> **操作系统**：Ubuntu 22.04 / 24.04 LTS（推荐）
> **架构**：FastAPI 后端 + React 前端 + MySQL + Redis + ZeroMQ

---

## 1. 系统架构

```
                    ┌─────────────────────────────────────────────────┐
                    │                  qt2-server                      │
                    │                                                  │
   CTP 行情 ───────►│  run_market_data.py                              │
   (期货交易所)      │    ├── CTP Gateway (openctp_ctp)                 │
                    │    ├── Tick Recorder → bin 落盘                   │
                    │    ├── ZMQ Publisher (PUB, port 5556)            │
                    │    └── Redis 快照写入                             │
                    │                                                  │
   浏览器 ─────────►│  run_api.py (FastAPI, port 18010)                │
   (前端 SPA)       │    ├── 静态文件 (frontend/dist)                   │
                    │    ├── /api/instruments  合约查询                 │
                    │    ├── /api/monitor      系统监控                 │
                    │    └── /api/config       配置查看                 │
                    │                                                  │
                    │  MySQL (port 21707)  合约信息、交易日历           │
                    │  Redis (port 21708)  监控上报、行情快照           │
                    └─────────────────────────────────────────────────┘
```

### 组件说明

| 组件 | 作用 | 端口 |
|------|------|------|
| FastAPI 后端 | REST API + 前端静态文件 | 18010 |
| 行情引擎 | CTP 行情接收、ZMQ 广播、落盘 | - |
| ZMQ Publisher | 行情实时广播 | 5556 |
| MySQL | 合约信息、交易日历 | 21707 |
| Redis | 监控指标、最新行情快照 | 21708 |

## 2. 环境拓扑与 Git 策略

| 环境 | 位置 | Git 策略 | 用途 |
|------|------|----------|------|
| **开发** | 本机 `~/work/Projects/qt2-server` | main 分支，直接 commit | 日常开发、调试 |
| **测试** | 测试机 `~/work/Projects/qt2-server` | `git pull origin main` | 集成测试、联调 |
| **生产** | 生产机 `~/prod/qt2-server` | `git checkout v1.0.0`（tag） | 稳定运行 |

```
GitHub (your-org/qt2-server)
  │
  ├── main ──────────────► 测试环境 git pull
  │   (持续集成)
  │
  └── v1.0.0 tag ─────────► 生产环境 git checkout
      (稳定发布)
```

### 版本号规范

遵循 SemVer：`v{major}.{minor}.{patch}`

| 变更类型 | 示例 |
|----------|------|
| 修 bug | v1.0.0 → v1.0.1 |
| 加功能（向后兼容） | v1.0.1 → v1.1.0 |
| 破坏性变更 | v1.1.0 → v2.0.0 |

### Tag vs Branch

| | Tag（采用） | Branch |
|---|---|---|
| 语义 | 标记发布版本，不可变 | 持续演进，可变 |
| 回滚 | `git checkout v1.0.0` 直接回滚 | 需找历史 commit |
| 审计 | `git tag -l` 列出所有生产版本 | 分支历史混杂 |

**结论：用 Tag。** 每次发布打一个 `v{version}` tag，生产环境 checkout tag 部署。

## 4. 安装 MySQL + Redis（Docker 方式）

### 4.1 创建数据目录

```bash
mkdir -p ~/qt2-infra
cd ~/qt2-infra
```

### 4.2 编写 docker-compose.yml

```yaml
version: '3.8'

services:
  mysql:
    image: mysql:8.0
    container_name: qt2_mysql
    restart: unless-stopped
    ports:
      - "21707:3306"
    environment:
      MYSQL_ROOT_PASSWORD: "你的强密码"
      MYSQL_DATABASE: "qt2"
      TZ: "Asia/Shanghai"
    volumes:
      - ./mysql_data:/var/lib/mysql
    command: >
      --character-set-server=utf8mb4
      --collation-server=utf8mb4_unicode_ci
      --default-time-zone='+8:00'

  redis:
    image: redis:7.0-alpine
    container_name: qt2_redis
    restart: unless-stopped
    ports:
      - "21708:6379"
    volumes:
      - ./redis_data:/data
    command: >
      redis-server
      --requirepass "你的强密码"
      --appendonly yes
    environment:
      TZ: "Asia/Shanghai"
```

### 4.3 启动

```bash
cd ~/qt2-infra
docker compose up -d

# 验证
docker compose ps
# 应显示 qt2_mysql 和 qt2_redis 状态为 running

# 测试 MySQL
docker exec -it qt2_mysql mysql -uroot -p"你的强密码" -e "SELECT VERSION();"

# 测试 Redis
docker exec -it qt2_redis redis-cli -a "你的强密码" PING
# 应返回 PONG
```

### 4.4 防火墙配置（可选）

如果仅本机访问，无需额外配置。如需允许局域网访问：

```bash
# MySQL
sudo ufw allow 21707/tcp

# Redis（不建议对外开放，仅本机）
# sudo ufw allow 21708/tcp

# API
sudo ufw allow 18010/tcp

# ZMQ
sudo ufw allow 5556/tcp
```

## 5. 安装 qt2-server

### 5.1 克隆代码

```bash
cd ~
git clone git@github.com:your-org/qt2-server.git
cd qt2-server
```

### 5.2 创建 Python 虚拟环境

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

> **注意**：`openctp_ctp` 包含 CTP 的 `.so` 动态链接库，仅支持 Linux x86_64。
> 如果 pip 安装失败，请确认系统架构和 glibc 版本（`ldd --version` 需 2.17+）。

### 5.3 配置 .env

```bash
cp .env.example .env
vim .env
```

编辑 `.env` 文件，填写实际值：

```ini
# 行情网关
GATEWAYS=ctp
CTP_MD_FRONT_ADDRESS=tcp://101.231.162.58:41213
CTP_SUBSCRIBE_EXCHANGES=CFFEX,SHFE,DCE,CZCE,INE,GFEX
CTP_SUBSCRIBE_ASSET_TYPES=FUTURE

# 数据库
DB_TYPE=mysql
DB_HOST=127.0.0.1
DB_PORT=21707
DB_USER=root
DB_PASSWORD=你的MySQL密码
DB_DATABASE=qt2

# Redis
REDIS_HOST=127.0.0.1
REDIS_PORT=21708
REDIS_PASSWORD=你的Redis密码
REDIS_DB=0

# ZeroMQ
ZMQ_BIND_URL=tcp://*:5556

# 落盘目录
DATA_DIR=data/raw

# UI 品牌名称（留空则不显示页脚）
APP_BRAND=Your-Corp

# Tushare 数据源（基础数据同步）
# 在 https://tushare.pro 注册获取 token
TUSHARE_TOKEN=你的TushareToken
```

### 5.4 初始化数据库

#### 5.4.1 建表

创建数据库和 `future_info`（期货合约信息）、`trade_calendar`（交易日历）两张基础表：

```bash
# 建库 + 建表（一条命令搞定）
mysql -h 127.0.0.1 -P 21707 -u root -p < schema/mysql/create_tables.sql
```

> 如果是从 quantlab/xquant 继承的已有数据库，只需补加新字段：
> ```bash
> mysql -h 127.0.0.1 -P 21707 -u root -p qt2 < schema/mysql/migrate_add_currency_settle_type.sql
> ```

#### 5.4.2 同步基础数据

从 Tushare 同步期货合约信息和交易日历：

```bash
source .venv/bin/activate

# 同步全部基础数据（期货合约信息 + 交易日历）
python run/run_sync_data.py

# 或分别同步
python run/run_sync_data.py --future-info          # 仅期货合约信息
python run/run_sync_data.py --trade-calendar       # 仅交易日历
python run/run_sync_data.py --trade-calendar --start 20250101 --end 20261231
```

> **注意**：同步需要有效的 Tushare Token，在 `.env` 中配置 `TUSHARE_TOKEN`。
> 建议每日盘前运行 `python run/run_sync_data.py --future-info` 更新合约信息。

### 5.5 构建前端

```bash
cd frontend
npm install
npm run build
cd ..
```

构建产物在 `frontend/dist/`，FastAPI 会自动 serve 这个目录。

## 6. 启动服务

### 6.1 启动 API 服务

```bash
source .venv/bin/activate
python run/run_api.py --host 0.0.0.0 --port 18010
```

验证：

```bash
curl http://127.0.0.1:18010/health
# 应返回 {"status":"ok"}

curl http://127.0.0.1:18010/api/config/
# 应返回配置信息（密码已脱敏）
```

### 6.2 启动行情引擎（仅交易时段）

```bash
source .venv/bin/activate
nohup python run/run_market_data.py --gateway ctp --assets future \
    > logs/md.log 2>&1 &
```

验证：

```bash
# 查看日志
tail -f logs/md.log

# 检查 ZMQ 状态
curl http://127.0.0.1:18010/api/monitor/zmq

# 检查 Redis 快照
curl http://127.0.0.1:18010/api/monitor/overview
```

### 6.3 访问前端

浏览器打开 `http://<服务器IP>:18010`

默认登录账号：`admin` / `admin`

## 7. 配置 systemd 服务（生产环境推荐）

### 7.1 创建 service 文件

```bash
mkdir -p ~/.config/systemd/user

cat > ~/.config/systemd/user/qt2-api.service << 'EOF'
[Unit]
Description=qt2-server API
After=network.target

[Service]
Type=simple
WorkingDirectory=%h/qt2-server
ExecStart=%h/qt2-server/.venv/bin/python run/run_api.py --host 0.0.0.0 --port 18010
Restart=on-failure
RestartSec=5
Environment=PYTHONUNBUFFERED=1

[Install]
WantedBy=default.target
EOF
```

### 7.2 启用服务

```bash
# 允许用户服务在退出登录后继续运行
sudo loginctl enable-linger $USER

# 加载并启动
systemctl --user daemon-reload
systemctl --user enable qt2-api
systemctl --user start qt2-api

# 验证
systemctl --user status qt2-api
```

### 7.3 进程管理常用命令

```bash
# 查看状态
systemctl --user status qt2-api

# 重启
systemctl --user restart qt2-api

# 停止
systemctl --user stop qt2-api

# 查看日志
journalctl --user -u qt2-api -f
# 或
tail -f ~/prod/qt2-server/logs/api.log
```

### 8.3 生产发布

#### 方式 A：一键部署脚本（推荐）

```bash
cd ~/work/Projects/qt2-server

# 更新 VERSION 文件
echo "1.0.1" > VERSION

# 部署（自动 commit VERSION + tag + push + 远程部署）
./scripts/deploy.sh
```

#### 方式 B：手动部署

```bash
# 1. 更新版本号
echo "1.0.1" > VERSION
git add VERSION
git commit -m "release: bump version to 1.0.1"
git push origin main

# 2. 打 tag
git tag v1.0.1
git push origin v1.0.1

# 3. 远程部署
ssh user@your-server
cd ~/prod/qt2-server
cp .env /tmp/qt2_deploy.env.bak
git fetch --tags
git checkout v1.0.1
cp /tmp/qt2_deploy.env.bak .env

# 4. 更新依赖 + 重建前端
source .venv/bin/activate
pip install -r requirements.txt
cd frontend && npm install && npm run build && cd ..

# 5. 重启服务
systemctl --user restart qt2-api

# 6. 冒烟测试
curl http://127.0.0.1:18010/health
curl http://127.0.0.1:18010/api/instruments/summary
```

### 8.4 回滚

```bash
# 一键回滚
./scripts/deploy.sh --rollback v1.0.0

# 或手动
ssh user@your-server
cd ~/prod/qt2-server
git fetch --tags
git checkout v1.0.0  # 回到上一个稳定版本
systemctl --user restart qt2-api
```

### 8.5 升级

```bash
cd ~/qt2-server

# 拉取最新代码
git fetch --tags
git checkout v1.0.7  # 替换为目标版本

# .env 已在 .gitignore 中，不会被覆盖

# 更新 Python 依赖（如有新增）
source .venv/bin/activate
pip install -r requirements.txt

# 重建前端

# 重启 API
systemctl --user restart qt2-api
```

## 11. 常见问题

### Q: pip install openctp_ctp 失败？

```
错误：找不到 openctp_ctp 的 .so 文件
```

**原因**：openctp_ctp 仅提供 Linux x86_64 的动态链接库。

**解决**：
1. 确认系统架构：`uname -m` 应为 `x86_64`
2. 确认 glibc 版本：`ldd --version` 需 2.17+
3. 如果是 macOS 或 ARM，需要在 Linux x86_64 机器上部署

### Q: MySQL 连接被拒绝？

```
错误：Can't connect to MySQL server on '127.0.0.1:21707'
```

**解决**：
```bash
# 检查容器状态
docker compose -f ~/qt2-infra/docker-compose.yml ps

# 如果未运行，启动
docker compose -f ~/qt2-infra/docker-compose.yml up -d

# 检查端口
ss -tlnp | grep 21707
```

### Q: Redis 认证失败？

```
错误：NOAUTH Authentication required
```

**解决**：确认 `.env` 中 `REDIS_PASSWORD` 与 docker-compose.yml 中的 `--requirepass` 一致。

### Q: ZMQ 端口被占用？

```
错误：ZMQ Publisher failed to bind at tcp://*:5556
```

**解决**：
```bash
# 查看占用进程
ss -tlnp | grep 5556

# 修改 .env 中的 ZMQ_BIND_URL 为其他端口
# ZMQ_BIND_URL=tcp://*:5557
```

### Q: 前端页面空白？

**原因**：前端未构建或构建产物路径不对。

**解决**：
```bash
cd frontend
npm install
npm run build
# 确认 dist/ 目录存在
ls dist/index.html
```

### Q: 行情引擎启动后没有数据？

**原因**：非交易时段，或 CTP 前置地址不对。

**解决**：
1. 确认在交易时段（9:30-11:30, 13:00-15:00）
2. 确认 `CTP_MD_FRONT_ADDRESS` 正确
3. 查看日志：`tail -f logs/md.log`

## 12. 备份

### MySQL 备份

```bash
# 导出全部数据
docker exec qt2_mysql mysqldump -uroot -p"密码" --all-databases > backup_$(date +%Y%m%d).sql

# 仅导出 qt2 库
docker exec qt2_mysql mysqldump -uroot -p"密码" qt2 > qt2_backup_$(date +%Y%m%d).sql
```

### Redis 备份

```bash
# 触发 RDB 快照
docker exec qt2_redis redis-cli -a "密码" BGSAVE

# 复制 dump.rdb
docker cp qt2_redis:/data/dump.rdb ./redis_backup_$(date +%Y%m%d).rdb
```

### 行情数据备份

```bash
# 打包落盘目录
tar -czf data_raw_$(date +%Y%m%d).tar.gz data/raw/
```

## 13. 性能调优建议

### MySQL

```ini
# 适用于 16GB 内存的服务器
[mysqld]
innodb_buffer_pool_size = 4G
innodb_log_file_size = 512M
max_connections = 200
query_cache_size = 0  # MySQL 8.0 已移除查询缓存
```

### Redis

```ini
# redis.conf
maxmemory 1gb
maxmemory-policy allkeys-lru
appendonly yes
appendfsync everysec
```

### 系统内核参数

```bash
# /etc/sysctl.conf
net.core.somaxconn = 65535
vm.overcommit_memory = 1

# 生效
sudo sysctl -p
```

## 14. 注意事项

- **生产环境不要手动改代码**，所有修复必须通过 commit → tag → checkout 部署
- **.env 不入 git**，生产环境的 .env 需要在部署后手动确认/恢复
- **前端必须 build**，生产环境用 `frontend/dist` 静态文件，不是 dev server
- **VERSION 文件必须与 tag 一致**，deploy.sh 会自动处理
- 部署前确认本地测试通过
- 未来生产环境可能迁移到其他服务器，只需修改部署脚本中的 `PROD_HOST` 和 `PROD_PATH`
